## Matriz mínima executada (run/build)

### Comando(s) executados

- `cargo test` (falhou em 1 teste unitário de semântica; evidência no relatório)
- `crab-pascal run ...` para fixtures:
  - `tests/fixtures/string_conformance.pas`
  - `tests/fixtures/class_property.pas`
  - `tests/fixtures/dict_trygetvalue_var.pas`
- `crab-pascal build ...` para as mesmas fixtures (sem toolchain C detectada no sistema)

### Observação central (run/build)

Quando **nenhum compilador C** foi detectado, o caminho `build` usou:

- “Runtime Interno do CrabPascal (sem dependências!)”
- “Executando diretamente da AST…”

Isso torna `build` **não equivalente** a “compilar C com gcc/clang”.

## Observações adicionais relevantes (evidências rápidas)

- Artefato C gerado em `build` para `string_conformance` chama `Length/Copy/Pos/Trim/...` diretamente, sem helpers `pascal_*`:
  - `tests/fixtures/string_conformance.c`:
    - `printf("%d\n", Length("año"));` (linha 6)
    - `printf("%d\n", Copy("abcdef", 2, 3));` (linha 7)
    - etc.
- `src/project/mod.rs` documenta explicitamente o fallback de AST quando toolchain C não existe.
